## 2. System Architecture

The system estimates expressive SMPL-X parameters from a sign-language video.
It combines whole-body, hand, and face estimators, then optionally applies
trained post-processing correctors.

```text
Input video
  -> Body estimation: SMPLest-X
  -> Hand estimation: WiLoR
  -> Face estimation: EMOCA
  -> Parameter fusion into SMPL-X
  -> Optional global_orient + transl corrector
  -> Optional hand wrist/finger corrector
  -> Optional 2D-guided upper-body corrector
  -> Temporal smoothing
  -> SMPL-X parameter export
  -> SMPL-X render video
  -> Side-by-side input/render comparison video
```

## 3. Independent CLI Programs

The four TOR CLI programs can be run independently.

```bash
python delivery/source/body_estimation_cli.py \
  --video datasets/videos/SignLanguage/SignLanguage_S2/SignLanguage_S2.mp4 \
  --output runs_tor/SignLanguage_S2 \
```

## 4. Final Integrated Pipeline

For the current best pipeline, use the one-process integrated program. It runs
base fusion and the optional post-processing stack in one command.

```bash
python delivery/source/integrated_postprocessed_pipeline_cli.py \
  --video datasets/videos/SignLanguage/SignLanguage_S2/SignLanguage_S2.mp4 \
  --output runs_tor/SignLanguage_S2_accurate \
  --name SignLanguage_S2 \
  --sequence SignLanguage_S2 \
  --device cuda \
  --postprocess-mode accurate \
  --precomputed-yolo-keypoints runs_tor/precomputed_yolo_pose_keypoints.json \
  --global-ckpt delivery/models/correctors/global/best_model.pt \
  --hand-ckpt delivery/models/correctors/hand/best_model.pt \
  --upper2d-ckpt delivery/models/correctors/upper2d/best_model.pt \
  --smplx-model SMPLest-X-Inference/human_models/human_model_files/smplx/SMPLX_NEUTRAL.npz \
  --eval-model SMPLest-X-Inference/human_models/human_model_files/smplx/SMPLX_FEMALE.npz \
  --smplestx-detector-stride 5 \
  --smplestx-batch-size 8 \
  --smplestx-inference-mode \
  --smplestx-single-gpu-model \
  --parallel-models
```

Post-processing modes:

| Mode | Meaning | YOLO keypoints required |
| --- | --- | --- |
| `none` | Base fusion only | No |
| `global` | Base fusion + global orientation/translation correction | No |
| `global_hand` | Base fusion + global + hand correction | No |
| `fast` | Alias for global + hand correction | No |
| `accurate` | Global + hand + 2D-guided upper-body correction | Yes |

Body-only execution, WiLoR/MANO and EMOCA toggles, realtime/streaming/batch
schedules, smoothing, zero-translation, and learned-corrector controls are
documented in `delivery/docs/RUN_CONFIGURATION_GUIDE.md`.

## 5. Stabilization And Requirement Control

```text

--stabilize-shape
--stabilize-lower-body
--stabilize-torso
```

For TOR review, generate comparable sample outputs for each requirement setting:

Default ablation variants:

| Variant | Stabilization | Post-processing |

## 7. Runtime And FPS Reporting

Use the one-process benchmark for fair runtime reporting:

```bash
SEQUENCES="SignLanguage_S2 SignLanguage_S3 SignLanguage_S4" \
RUN_ROOT=/project/lt200246-mmacma/khtun/video2smplx_integrated_oneprocess_benchmark \
YOLO_KEYPOINTS=/project/lt200246-mmacma/khtun/video2smplx_keypoints/evaluation/precomputed_yolo_pose_keypoints.json \
sbatch delivery/scripts/slurm/benchmarks/benchmark_integrated_oneprocess.sh
```

Main output:

```text
<RUN_ROOT>/evaluation/oneprocess_runtime_summary.csv
```

Important columns:

| Column | Meaning |
| --- | --- |
| `total_fps` | Includes model loading, inference, post-processing, smoothing, and rendering |
| `no_initial_load_total_fps` | Removes model import/load time, keeps rendering |
| `no_initial_load_no_render_fps` | Removes model import/load time and rendering |
| `steady_state_model_fps` | Uses per-frame model timing after warmup frames |

Measured with precomputed YOLO keypoints on S2/S3/S4, the accurate
post-processing stack adds about 13 ms/frame. The major remaining runtime cost
is the base SMPLest-X/WiLoR/EMOCA inference.

Current measured values are:

| Runtime scope | Result |
| --- | ---: |
| SMPLest-X-only normal working throughput after warm-up | 19.59 FPS |
| Full foundation-model steady throughput | 6.76 FPS |
| Final pipeline without initial load or rendering | 3.57 FPS |
| Final pipeline including rendering, with precomputed YOLO | 1.98 FPS |
| Standalone YOLO keypoint preprocessing | 3.35 FPS |

The SMPLest-X-only value must not be reported as full-pipeline FPS. For unseen
videos, YOLO preprocessing is either an additional pass or an online pipeline
stage and must be reported separately.

## 11. Review Notes

- The four base CLI programs satisfy the independent-program requirement.
- The integrated CLI is provided for practical one-command execution and FPS
  benchmarking.
- The accurate mode uses precomputed 2D keypoints to reduce post-processing
  runtime.
- Ablation sample generation should be run before final handover so reviewers
  can inspect visible differences between stabilization and post-processing
  settings.
